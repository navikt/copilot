Juli 2026 handler om tre parallelle bevegelser. For det første en bølge av nye frontlinjemodeller: Anthropics **Claude Opus 5** kom som månedens tydeligste enkeltnyhet — en «near-frontier» toppmodell med justerbar innsatskontroll (effort) — sammen med OpenAIs GPT-5.6-familie, Moonshots open-weight Kimi K2.7 Code og Google Gemini 3.6 Flash. For det andre modnes den agentiske sikkerheten fra ren *deteksjon* til *remediering*: code scanning viser nå AI-drevne funn på pull requests, en agent kan foreslå og validere rettelser automatisk, og GitHub Code Quality går i GA. For det tredje strammes styring og kostnadsinnsyn til med AI-kredittpotter, individuell forbruksoversikt, sentralstyrt OpenTelemetry/MDM og et nytt impact dashboard. For Nav betyr dette at valgene blir flere og kraftigere samtidig som verktøyene for å styre kostnad, sikkerhet og etterlevelse rundt AI-bruken blir vesentlig bedre.

## 1. Claude Opus 5 er generelt tilgjengelig — månedens toppnyhet

Anthropic lanserte Claude Opus 5 (`claude-opus-5`) fredag 24. juli 2026, og modellen ble generelt tilgjengelig (GA) i GitHub Copilot samme dag. Opus 5 er Anthropics nye toppmodell og posisjoneres som «near-frontier» — tett opp mot de sterkeste modellene på markedet, men til en vesentlig lavere kostnad per oppgave. Prisen er den samme som Opus 4.8: $5 per 1M input-tokens og $25 per 1M output-tokens. En «fast mode» gir ~2,5x raskere svar til 2x grunnpris.

Hovednyheten er **justerbar innsatskontroll** (effort control). Du kan styre hvor hardt modellen jobber — fra lave nivåer for enkle oppgaver til høyere nivåer som `xhigh` og `max` for det tyngste arbeidet. I praksis lar dette deg bytte mellom kostnad og kapasitet på samme modell, slik at du slipper å betale for maksimal resonnering på oppgaver som ikke trenger det. Anthropic oppgir at Opus 5 på max effort ligger innenfor 0,5 % av Fable 5s toppnivå på CursorBench 3.2 til rundt halve kostnaden, og at den mer enn dobler Opus 4.8s resultat på Frontier-Bench v0.1.

Opus 5 er tilgjengelig for Pro+, Max, Business og Enterprise (ikke Pro/Free), og er av som standard for Business/Enterprise — administrator må aktivere policyen i Copilot-innstillingene. Opus 4.8 er fortsatt tilgjengelig; lanseringen medfører ingen avvikling. Merk at Opus 5 har innebygde ekstra sikkerhetstiltak mot høyrisiko cyber-innhold, som i noen tilfeller kan blokkere sikkerhetsrelaterte forespørsler. For Nav er dette det nye førstevalget der vi tidligere pekte på Opus 4.6/4.8 — dyp risikovurdering og sikkerhetskritisk kode — og den justerbare innsatskontrollen gjør Opus-klassens prising mer forsvarlig i daglig bruk.

**Kilder:** [Claude Opus 5](https://www.anthropic.com/news/claude-opus-5) (Anthropic, 24. juli 2026); [Claude Opus 5 is now available in GitHub Copilot](https://github.blog/changelog/2026-07-24-claude-opus-5-is-now-available-in-github-copilot/) (GitHub Changelog, 24. juli 2026)

## 2. Fire nye modeller i modellvelgeren: GPT-5.6, Kimi K2.7 Code og Gemini 3.6 Flash

Ved siden av Opus 5 kom fire andre modeller til i løpet av juli. **OpenAIs GPT-5.6-familie** (9. juli) er delt i tre varianter: *Sol* (Powerful, høyest reasoning, for komplekse kodebaser og langvarige agentoppgaver; $5/$30 per 1M tokens), *Terra* (Versatile, balansert standardvalg for daglig koding; $2.50/$15) og *Luna* (Lightweight, rask og billig for enkle oppgaver; $1.00/$6.00). Sol krever Pro+, Max, Business eller Enterprise, mens Terra og Luna også er tilgjengelig for Pro.

**Kimi K2.7 Code** fra Moonshot AI (1. juli) er den første open-weight-modellen som kan velges direkte i modellvelgeren — et rimeligere alternativ for kodingsarbeidsflyter til $0.95/$4.00 per 1M tokens. Den er GitHub-hostet på Azure og faktureres til leverandørens listepris. **Gemini 3.6 Flash** fra Google (21. juli) er optimalisert for web- og apputvikling og lengre agentoppgaver, med konfigurerbar reasoning-innsats og parallell verktøybruk; den koster $1.50/$7.50 og viste i tidlige tester høyere fullføringsgrad og bedre token-effektivitet enn Gemini 3.5 Flash.

Alle tre er av som standard for Business og Enterprise og krever at administrator aktiverer policyen i Copilot-innstillingene. GitHub anbefaler at administratorer vurderer open-weight-modeller opp mot egne krav til sikkerhet, compliance og dataforvaltning før de aktiveres.

## 3. Slik velger du riktig modell — uten å sprenge kvoten

Med fem nye modeller på plass har redaksjonen laget en praktisk veiledning for hvordan man velger fornuftig og tester ansvarlig. Kortversjonen: bruk **Luna** til rask rutinejobb, **Terra** (eller Auto) til vanlig feature-utvikling, **Gemini 3.6 Flash** til agenter som skal jobbe med mange verktøy (den «roter minst»), **Sol** til kompleks arkitektur og vriene bugs i store repoer, og **Claude Opus 5** til dyp risikovurdering og sikkerhetskritisk kode — med effort skrudd opp bare når det trengs. **Kimi K2.7 Code** er et rimelig alternativ i agent-løkker, men må alltid «tenke» og kan ikke gi lynraske svar uten resonnering.

De nye modellene er tillegg, ikke erstatninger. Anthropic-modellene er fortsatt best på norsk tekst og microcopy, Gemini 3.1 Pro overtar rollen for research og lange kontekstvinduer etter Gemini 2.5 Pro, og Claude Sonnet 5 til kampanjepris ($2/$10 ut august) er fortsatt svært konkurransedyktig i Versatile-klassen. **Auto**-modus velger en passende modell med innebygd kostnadsrabatt — retningslinjene forteller deg i det minste *hvorfor* du eventuelt overstyrer den.

## 5. AI-sikkerhetsfunn på pull requests og CodeQL 2.26.0

GitHub code scanning viser nå AI-drevne sikkerhetsfunn direkte på pull requests. Funksjonaliteten utvider sårbarhetsdekningen til språk og rammeverk som ikke dekkes av CodeQLs innebygde analyse, slik at blinde flekker i kodebasen reduseres. Funn vises i PR-visningen som vanlige code scanning-varsler, men merket med «AI» slik at de er lette å skille fra CodeQL-resultater. Funksjonen aktiveres på enterprise-nivå først, deretter på organisasjon eller repository.

Samtidig kom **CodeQL 2.26.0** med tre viktige oppdateringer: støtte for å analysere Kotlin-kode opp til versjon 2.4.0, en ny query som oppdager system-prompt-injeksjon i JavaScript/TypeScript (svært relevant når flere team bygger AI-integrasjoner), og oppdaterte Go-modeller slik at `go/log-injection` og `go/clear-text-logging` nå fanger problemer i kode som bruker `log/slog`-pakken.

**Kilder:** [Code scanning shows AI security detections on pull requests](https://github.blog/changelog/2026-07-14-code-scanning-shows-ai-security-detections-on-pull-requests) (GitHub Changelog, 14. juli 2026); [CodeQL 2.26.0 adds Kotlin 2.4.0 support and AI prompt injection detection](https://github.blog/changelog/2026-07-10-codeql-2-26-0-adds-kotlin-2-4-0-support-and-ai-prompt-injection-detection) (GitHub Changelog, 10. juli 2026)

## 6. Agentisk autofix for code scanning-varsler

Der de AI-drevne deteksjonene finner og rapporterer sårbarheter, tar agentisk autofix (public preview) seg av selve *rettingen*. Funksjonen retter automatisk varsler fra CodeQL og tredjepartsverktøy: en agent utforsker relevante filer, genererer et forslag til rettelse, validerer at rettelsen fungerer ved å kjøre CodeQL på nytt, itererer om nødvendig, og åpner en utkast-PR til gjennomgang. Generering av en rettelse tar typisk 2–4 minutter.

Autofix kan utløses på tre måter: tildel enkeltvarsler direkte til Copilot, velg flere varsler samlet i repositoryets sikkerhetslister eller kampanjer, eller tildel varsler via REST API. Funksjonen krever GitHub Code Security- eller Advanced Security-lisens samt en Copilot-lisens med cloud-agent aktivert, og organisasjons- og enterprise-admins kan slå den av via innstillinger eller policy. I forhåndsvisningen forbruker autofix AI-kreditter (kun når rettelser faktisk kjøres) og trekker på GitHub Actions-minutter — foreløpig uten at forbruket skilles ut separat fra annen Copilot-aktivitet.

**Kilde:** [Agentic autofix for code scanning alerts in public preview](https://github.blog/changelog/2026-07-10-agentic-autofix-for-code-scanning-alerts-in-public-preview/) (GitHub Changelog, 10. juli 2026)

## 9. cplt: sikkerhetsherding med namespaces, tvunget proxy og upstream-chaining

[cplt](https://github.com/navikt/cplt) — Navs sandbox for AI-kodingsagenter — fikk i juli en runde sikkerhetsherding og tre nye funksjoner, som lag i et forsvar-i-dybden-oppsett. På Linux kan agenten nå pakkes inn i **Bubblewrap-namespaces** (PID/IPC/UTS/cgroup/user) med en privat `/tmp`, oppå Landlock + seccomp-BPF — agenten kan ikke lenger se eller signalisere prosesser på verten. Dette er bevisst ikke en nettverksgrense og ikke full filsystem-konfidensialitet; nettverkskontrollen ligger fortsatt hos proxyen og Landlock-portreglene.

**Proxy-forced modus** (`proxy.forced`, av som standard) lukker en tidligere bypass ved å gjøre proxyen obligatorisk og begrense kernel-egress til proxy-porten alene, med fail-closed oppstart. Håndhevingen er asymmetrisk: macOS pinner fullt til `localhost`, mens Linux har en kjent, smal portbasert restkanal. **Upstream proxy-chaining** (`proxy.upstream`) lar team bak en bedriftsproxy videresende CONNECT-tunneler gjennom den — samtidig som cplt beholder egen domenefiltrering, logging og portsjekker, håndhevet *før* videresending. I samme bølge kom best-effort Landlock-ABI på eldre kjerner, tetting av gh/git-guard-bypasses, fikser for loopback-SSRF og en token-lekkasje, samt respekt for verktøystier fra miljøvariabler.

**Kilder:** [navikt/cplt#64](https://github.com/navikt/cplt/pull/64), [navikt/cplt#117](https://github.com/navikt/cplt/pull/117), [navikt/cplt#125](https://github.com/navikt/cplt/pull/125), [SECURITY.md](https://github.com/navikt/cplt/blob/main/SECURITY.md) (cplt, juli 2026)

## 12. Sentralstyrt OpenTelemetry og MDM-distribusjon

Enterprise-administratorer kan nå bestemme hvor GitHub Copilot sender **OpenTelemetry-data** (OTel), slik at telemetri flyter til en godkjent collector uten at hver utvikler må sette `OTEL_*`-miljøvariabler manuelt. Konfigurasjonen leveres gjennom en `telemetry`-blokk i enterprise-managed settings og gjelder både Copilot Chat-utvidelsen i VS Code og agentvertsprosessen bak Copilot CLI. Administrator kan styre OTLP-endepunkt og transportprotokoll, tjenestenavn og ressursattributter, eksportør-headere, og om prompt-, respons- og verktøyinnhold skal fanges. En sentralstyrt verdi «vinner» alltid over miljøvariabler og brukerinnstillinger.

I tillegg kan administratorer nå distribuere sentralstyrte **Copilot-innstillinger via MDM** gjennom tre kanaler: native MDM (Intune, Jamf eller Group Policy), server-managed (løst fra den innloggede GitHub-kontoen) og filbasert (`managed-settings.json` deployet med Chef, Puppet, Ansible eller lignende). Innstillingene gjelder konsistent på tvers av VS Code og Copilot CLI, uavhengig av hvordan utvikleren logger inn.

**Kilder:** [Enterprise-managed OpenTelemetry export for VS Code and CLI](https://github.blog/changelog/2026-07-08-enterprise-managed-opentelemetry-export-for-vs-code-and-cli) (GitHub Changelog, 8. juli 2026); [Deploy managed Copilot settings via MDM in VS Code and CLI](https://github.blog/changelog/2026-07-08-deploy-managed-copilot-settings-via-mdm-in-vs-code-and-cli) (GitHub Changelog, 8. juli 2026)

## 13. Agentstyring i GitHub Issues: godkjenninger, konfidens og begrunnelser

Agent-automatiseringer som merker, tilordner og lukker issues får nå innebygd styring direkte i GitHub Issues (public preview) via tre nye funksjoner. **Godkjenninger** lar deg sette opp automatiseringen til å *foreslå* endringer i stedet for å gjennomføre dem direkte — forslagene venter i et panel på issuet, og du godkjenner eller avslår enkeltvis eller samlet. **Konfidensnivåer** klassifiserer hver handling som høy, middels eller lav: høy-konfidens-endringer gjennomføres automatisk, mens middels og lav holdes som forslag til manuell gjennomgang.

**Begrunnelser** gir et revisjonsspor: alle handlinger, automatiske eller ventende, loggføres med resonnementet bak, slik at du kan se hvorfor agenten gjør en endring før du tar en beslutning. Du kan bruke `has:suggestions` i issue-søk for å finne issues med ventende forslag, og repository-admins kan konfigurere terskelverdier for konfidens per repository.

**Kilde:** [Agent automation controls in GitHub Issues in public preview](https://github.blog/changelog/2026-07-23-agent-automation-controls-in-github-issues-in-public-preview) (GitHub Changelog, 23. juli 2026)

## 16. Copilot cloud-agent for Linear er generelt tilgjengelig

Copilot cloud-agent for Linear er nå generelt tilgjengelig (GA). Agenten er en autonom bakgrunnsagent: når du tildeler den et Linear-issue, analyserer den innholdet, jobber selvstendig i et flyktig miljø drevet av GitHub Actions, og åpner en utkast-PR. Fremdriften strømmes fortløpende til Linear-issuets aktivitetslogg, og agenten ber om PR-gjennomgang når den er ferdig.

Du kan styre agenten per issue eller for hele arbeidsområdet: velge AI-modell, peke på repository-baserte custom agents, sette mål- og arbeidsbranch, og gi nye instruksjoner underveis ved å nevne Copilot i en kommentar. Funksjonen er tilgjengelig for Copilot Pro, Pro+, Business og Enterprise. Installasjon skjer ved å hente appen «GitHub Copilot for Linear» fra GitHub Marketplace, og krever organisasjonseier-rettigheter i GitHub og admin-rettigheter i Linear-arbeidsområdet.
