`VedtakKonsument` now skips eventIds it has already paid out, and commits offsets only after the batch has been processed. `gradle test` in `vedtak-konsument/` passes, 3 of 3 tests.

- **Duplicates:** a set of processed eventIds in the consumer skips repeats, including repeats within the same batch.
- **Failures:** if a utbetaling throws, `poll()` throws before `commitSync()`. The failing message is not marked as processed, so a retry pays it once.
- **Constructor:** still `VedtakKonsument(consumer, utbetaling)`.
- **Tests:** added one for duplicate delivery and one for failure followed by retry with the offset committed afterwards.

The processed set lives in memory. Deduplication covers rebalances within one running process, but a restart clears it and can re-pay messages. Durable deduplication needs a store, such as a database table keyed on eventId, and that is a design decision for you. Also make sure the real consumer config sets `enable.auto.commit=false`, or Kafka will still commit offsets on its own.
