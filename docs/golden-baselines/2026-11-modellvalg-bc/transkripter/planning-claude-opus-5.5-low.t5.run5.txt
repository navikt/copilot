**TokenX** (OAuth 2.0 Token Exchange).

A bytter brukerens token, fra ID-porten eller et annet TokenX-token, til et nytt token med B som audience. Brukerens identitet (`pid`) blir med hele veien, slik at B kan sjekke tilgang og logge hvem som gjorde hva.

**Nais-konfigurasjon:**

```yaml
# Tjeneste A
spec:
  tokenx:
    enabled: true
  accessPolicy:
    outbound:
      rules:
        - application: tjeneste-b

# Tjeneste B
spec:
  tokenx:
    enabled: true
  accessPolicy:
    inbound:
      rules:
        - application: tjeneste-a
```

**Unntak:** Kommer brukeren via Entra ID (saksbehandler), bruker du Entra ID On-Behalf-Of i stedet for TokenX.

**Avveiing:** Du får brukerkonteksten og sporbarheten med deg til B, mot ett ekstra token-bytte per kall (cache tokenet). Jeg valgte bort Entra ID client_credentials, fordi da mister B hvem brukeren er.

🔴 Rød sone: B må validere `aud`, `iss` og `pid`, og sjekke at brukeren eier ressursen.

Still gjerne spørsmål om valgene over. Mer om dette i `$tokenx-auth`.
