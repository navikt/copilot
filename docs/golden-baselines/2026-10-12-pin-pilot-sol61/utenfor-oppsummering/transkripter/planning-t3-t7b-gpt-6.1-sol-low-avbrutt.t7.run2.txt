    --- src/main/kotlin/no/nav/demo/Soknad.kt ---
    package no.nav.demo

    import tools.jackson.databind.json.JsonMapper
    import tools.jackson.module.kotlin.kotlinModule
    import tools.jackson.module.kotlin.readValue
    import org.apache.kafka.clients.producer.KafkaProducer
    import org.apache.kafka.clients.producer.ProducerRecord
    import java.time.LocalDate

    data class SokerDto(val fnr: String, val navn: String)

    data class SoknadMottattMelding(val soknadId: String, val mottatt: LocalDate)

    val mapper: JsonMapper = JsonMapper.builder()
    .addModule(kotlinModule())
    .build()

    fun lesSoker(json: String): SokerDto = mapper.readValue(json)

    fun sendMottatt(producer: KafkaProducer<String, String>, melding: SoknadMottattMelding) {
    producer.send(ProducerRecord("soknad-mottatt", melding.soknadId,
    mapper.writeValueAsString(melding)))
    }

    fun sendSoker(producer: KafkaProducer<String, String>, soker: SokerDto) {
    producer.send(ProducerRecord("soker-oppdatert", soker.fnr, mapper.writeValueAsString(soker)))
    }

**Migreringen er riktig på kodenivå, men atferdskompatibiliteten er ikke verifisert.** Jeg vurderte commit `cd3c10c` mot `b0deead`. Ingen filer er endret.

Det som er riktig:
- Jackson-avhengighetene og importene er flyttet til `tools.jackson`, med samme versjon `3.1.0`.
- Mapperen bruker builder og registrerer Kotlin-modulen.
- Fjerningen av `jackson-datatype-jsr310` er riktig. Java Time-støtten er innebygd i Jackson 3, og standardformatet for `LocalDate` viderefører den tidligere ISO-dato-konfigurasjonen.
- Ktor bruker **kotlinx.serialization**, ikke Jackson. Ktor `3.0.0` er derfor ikke en Jackson-3-blokkering her.
- Ingen gamle Jackson-importer, mapper-mutasjoner eller `JsonNode.map`-kall finnes i kildekoden.

**To kompatibilitetsendringer bør avklares før merge**, begge ved mapperen i `src/main/kotlin/no/nav/demo/Soknad.kt:14–18`:
1. Jackson 3 sorterer properties alfabetisk. Kafka-meldingene får dermed annen feltrekkefølge: `mottatt` før `soknadId`, og `fnr` før `navn`. Felter og verdier er uendret, men konsumenter som sammenligner rå JSON-strenger, påvirkes.
2. `FAIL_ON_TRAILING_TOKENS` er nå aktivert som standard. `lesSoker` vil avvise input med flere JSON-verdier som den gamle mapperen kunne akseptere. Dette er strengere parsing, men ikke identisk atferd.

**Verifisering er blokkert av byggemiljøet.** Repoet mangler Gradle-wrapper og tester. Forsøket med installert Gradle feilet under konfigurering med `> 27` på JDK 27, før kompilering og dependency-resolusjon. Oppslag etter alternativ JDK ble nektet. Derfor er hverken bygget eller fravær av transitiv Jackson 2 bekreftet. Før merge bør et kompatibelt JDK brukes til build og dependency-sjekk, og karakteriseringstester sammenligne JSON-payloadene og `lesSoker` mellom Jackson 2 og 3.
